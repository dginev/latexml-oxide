ab_audit run: convert a paper list with two binaries into <out>/A/<id>/ and <out>/B/<id>/, then compare them.

It refuses to start unless each binary’s stamped revision (--version’s (revision <sha>), or the conversion banner of a binary built before that) is the commit the caller expects: 64x r1 and 64ra ran their A/Bs on stale binaries. A historical replay names the stamp it accepts with --accept-stamp <sha>, and the TSV header prints it; there is no silent bypass. It also refuses:

  • two binaries with one stamp but different expected commits, unless --accept-same-stamp (the stamp then tells them apart by nothing; a loud line is printed either way);
  • a binary older than its expected commit (file mtime before the commit’s committer time, when git -C <repo> resolves the commit);
  • two byte-identical binaries, unless --allow-same-binary;
  • an empty paper list.

What the stamp cannot prove. build.rs re-runs only when LATEXML_GIT_SHA changes, not when HEAD moves (#528), so a target directory keeps the stamp of its first build: five distinct binaries of 2026-10-10/11 (64u, 64ufix, 64zb, 64zc, 64w) all say 9569ca27a7. A build must set LATEXML_GIT_SHA=$(git rev-parse --short HEAD) for the stamp to mean anything, and even then a dirty tree is not reflected. The mtime check catches only a binary built before its commit, not one built after it from other sources; the binary hash (recorded per conversion) tells two builds apart but not which source each came from. The mtime is weak evidence: cp without -p or a touch gives any old binary a fresh mtime, and an amend or rebase moves the commit’s committer time past a binary that does hold its code (refused until rebuilt, the safe side).

Per paper and binary, the payload brief’s standard command: a fresh directory, ulimit -v 8912896, timeout 300, taskset -c <cores>, --preload=ar5iv.sty --timeout=240 --dest=out.xml --log=out.log. A finished conversion leaves meta.tsv (stamp, binary hash, settings hash, exit code, seconds, timeout); a rerun skips every paper whose meta.tsv names the same stamp, binary hash and settings (dump dir, timeouts, memory, TeX Live bin, corpus).
