A native answer to \__fp_parse:n and \__fp_parse_o:n (expl3-code.tex:17313-17339), the doors of l3fp: \fp_set:Nn, \fp_eval:n, \fp_compare:nNnTF, xfp’s \fpeval, siunitx and l3draw all come through them. It takes one \fp_set:Nn from about 40k token reads to a few hundred (pgf-interference’s pixel loop, docs/performance/PERFORMANCE.md).

The hook. Both doors stay the format’s own macros. Their expansion is … \exp:w \__fp_parse_operand:Nw \c__fp_prec_end_int \__fp_parse_expand:w <expression> \s__fp_expr_mark \__fp_parse_infix_end:N \s__fp_expr_stop …, the only such call. \__fp_parse_operand:Nw keeps its body too, and carries a native call (operand_call, SpecialCall::Native): when the gullet expands it in full and the input is that shape, the expression is read from the pushback without consuming it. The answer leaves what the macro’s own run leaves for \__fp_parse_after:ww, \exp_end_continue_f:w <fp>@ \__fp_parse_infix_end:N (\s__fp_expr_stop still on the input), through the ordinary path of a macro’s expansion (invoke_expansion, whose inherit_field_prov a printed \@title needs). On any other call, and on anything the native path does not handle with certainty (Decline: an unknown token, a tuple, nan, rand, a flag or a message of any kind, a tab mark that ends a cell), nothing has happened and the macro runs as defined over the input as it stands. So \meaning, the prefixes and a one-step \exp_after:wN of either door and of this macro are the format’s, and a tuple, a flag or a message is the macro’s own.

While it may answer. Only while l3fp is what this module ports: the meanings of the \__fp_…, \c__fp_…, \s__fp… and \c_…_fp names are watched (watch_meanings), and an assignment that changes one, however local, ends the native path for the rest of the conversion. A document’s new word (\fp_new_variable:n) has no meaning to change: the parser declines any word it does not know. So a control sequence the parser knows by name means what it did at the install.

The arithmetic is a port. + - * / and sqrt round correctly in the TeX, so exact integers give the same digits (num.rs). exp, ln, ^ and the trigonometric functions do not, so func.rs and fixed.rs translate their block operations and tables one for one, truncations included. No f64 comes near a value.

LATEXML_L3FP_NATIVE=0 installs nothing. LATEXML_L3FP_CHECK=1 runs the macro’s own run on every answer and reports an Error naming the argument if the tokens differ; it compares tokens only, not what a run reports (kit/l3fp_oracle.sh holds the arithmetic against pdflatex as well). LATEXML_L3FP_TRACE=1 counts answers and fallbacks by reason, printed on stderr at the thread’s end.

Installed at the format’s end, after the dump’s apply: the dump does not change, and a later raw load of expl3-code.tex simply wins (and trips the watch). Only over the l3fp this port was made from (native_applies): another year’s l3fp stays entirely the macros’. No code here relies on unwinding (maxperf aborts on a panic).
