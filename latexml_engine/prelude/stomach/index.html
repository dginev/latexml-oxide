Structs§

Stomach
The Stomach is responsible for digesting tokens into boxes, lists, etc.
StomachMark
What a speculative digestion — one whose output is discarded and whose assignments its journal undoes (the frontmatter’s title-page runs, rehearsals and label reads) — must leave as it found it besides its assignments: the stack of tokens being invoked and the active conditionals. Taken before the run, put back however it ends (StomachMark::restore): the document never runs the run’s tokens. A runaway Fatal the run raised and discarded (a Stomach:Recursion) left the whole MAXSTACK of tokens on the stack, and the document’s next digestion failed its first push with a ghost Fatal of its own (2502.10606’s \thanks inside a \thanks, all 8,054 words lost, as clear_token_stack’s 2410.07647); a \fi of the run’s closing a conditional the document opened before it left that conditional closed for the document, whose own \fi then had none (2003.03814: CUP-JNL-DCE.cls:505 \keywords leaves its \ifx open, \fi inside \@keywords, which \printkeywords balances; the title-page run’s \printkeywords closed it and the class’s real \maketitle raised “Didn’t expect a \fi”). Runs that read one text in pieces share its conditionals as TeX reads it, in one pass: the observer rehearses an author list block by block, a conditional opened in one block’s run closed in the next’s (2606.17718’s \IEEEauthorblockA{… \if… E-mail: …} \else … \fi), so its shadow takes the mark around the whole sequence and each rehearsal puts back only its token stack (truncate_token_stack). Put back on drop too, so every exit restores — a ? that propagates a run’s Fatal included (review rev135c S1) —, except while a panic unwinds (the state may be borrowed).

PUT_BACK_BRACE

PUT_BACK_LIVE
The serial of the one live put-back mark (0: none), global.
TEMPLATE_BRACE_OPEN
Bound in an alignment cell’s frame while its template’s { ($\displaystyle{##}$) is open — latexml_engine tex_box.rs \lx@template@bgroup/\lx@template@egroup; a } that would close the frame closes it (close_template_brace).
UNENDED
The whatsit property of a construct the document ended inside of: \end{document} came while its arguments or body were still being digested and abandoned their groups (tex.web §1335), so it never ended — whatever came after the defect that left it open (a section, a bibliography) is inside it. Constructor::digest_to_whatsit sets it (ends_inside_groups moved during the digestion); the document lets every element such a whatsit opens auto-close (Document::open_element), Perl’s per-node _autoclose (Document.pm canAutoClose), so that structure closes it instead of being held inside as malformed:* (1611.05714, 1101.1959, physics0505113, math9805003). OXIDIZED_DESIGN #542.

abandon_stack_frame

align_error
tex.web §1127 align_error: a tab, \cr or \span that reaches the stomach while the alignment count is not 0 — the cell left a brace unbalanced, so the gullet did not take it for the cell’s end (§342) — gets the brace TeX supposes was omitted: count −1 or −2 (the cell’s } closed one more group than it opened, a} &=& b) inserts a { (“Missing { inserted”), count +1 or +2 ({a & b}, \textbf{a & b}) a } (“Missing } inserted”), and the column end is read again behind it, now at count 0, so the v-part runs and the cell ends as the template says (§789). The ledger moves as TeX’s does: align_error steps the count towards 0 and ins_error’s back_input (§325) retracts the inserted brace, which counts again when it is read. A larger count (abs(align_state)>2, “Misplaced &”) is left to the cell’s reader, as is a count past the v-part’s 1000000 (the column’s own end). Before, the column end was taken for the cell’s end with no v-part: an eqnarray/amsmath cell left its template’s math open (pdflatex 1 error, ours 17: “Attempt to close a group that switched to mode math”), and a tabular cell’s {a & b} lost a without a word. Perl has no align_error (KNOWN_PERL_ERRORS #923). Whether it fired. formula_continues_past_par
Whether the inline formula a \par is read in goes on past it: OXIDIZED_DESIGN #553 as narrowed (66w). The input is looked at, not read (gullet::peek_upcoming_tokens, unexpanded, each token by its current meaning), as far as the formula’s would-be closer — the next $ or \) — within the paragraph after the \par. The formula continues when the material before that closer holds a math-only token (a _/^, or a command that is LookaheadCommand::MathOnly): the author split the formula with a blank line and the math goes on (hep-th9402135 $Z_{YM}(\epsilon) = ⏎⏎ \int_{\cal A} … D A$, whose ending put every later $ of the paragraph out of step, Fatal TooManyErrors). It does not when no math-only token comes first — that $ opens the next paragraph’s own formula, and the \par ends this one (tex.web §1047, a forgotten $) — nor on any doubt: no closer before the paragraph’s end (PAR_LOOKAHEAD_STOPS), the bounds (PAR_LOOKAHEAD_LINES, PAR_LOOKAHEAD_TOKENS, PAR_LOOKAHEAD_CHARS), a closer inside a group, a bracket or a $$, a } closing a group the look-ahead did not see open, an &, a command it cannot follow (LookaheadCommand::GiveUp: \verb|make_all|, \lstinline, \url). The arguments of a command that is not math-only are not looked into: a * right after it, then every […] and {…} group in a row (\cite[p.~2]{smith_2001}, \ref*{eq_1}, \includegraphics[width=1cm]{fig_1}, \citep[e.g.][]{a_b}) — their scripts may be a key’s or a file name’s, never typeset; any other group is ({\cf^{1}/G}$, \left[0,1\right)). The look-ahead starts after the judged \par, its leading \pars and spaces skipped — an \obeylines line end’s active ^^M among them (hep-ph9809328).

soft_cap_from_ceiling
Derive the cooperative soft-RSS budget (bytes) from the hard --max-memory ceiling (MiB). The soft fuse sits at 75% of the ceiling, leaving ~25% headroom for the post-processing phase (libxml DOM + XSLT) that runs above digestion and which this cooperative guard cannot see. 0 in → 0 out (disabled), so --max-memory=0 disables the whole memory limit. This keeps --max-memory the single knob: the hard Watchdog rides the ceiling, this fuse rides a fixed fraction below it — no independent second number.
soft_yield_min_boxes
Cached: this sits on the per-seam yield predicate, which the 131 MB witness evaluates tens of millions of times — an std::env::var there would be its own hotspot.
spill_mark_kb
The resident set (KB) at which this conversion spills: spill_watermark_bytes above its starting RSS, never closer to the fuse (process RSS, it guards the machine) than two watermarks — the headroom the fuse fraction was calibrated for (a half-of-fuse mark crept into the fuse, spill_watermark_bytes). With the default third-of-fuse watermark that cap is the watermark itself, so under a fuse the mark is absolute, as before the conversion’s baseline (revSTRM: a worker near its recycle threshold must not spill later than the calibration allows); the baseline moves the mark only without a fuse or under a smaller calibration watermark. Order independence rests on a switched conversion writing the eager XML, not on the mark. A zero watermark (a test’s or a calibration’s LATEXML_SPILL_AT_MIB=0) puts every seam over it.
spill_watermark_bytes
The RAM watermark, in bytes above the conversion’s starting RSS (spill_mark_kb), at which streaming pass 1 begins spilling closed subtrees to disk — the second derived quantity of the single --max-memory knob, and deliberately NOT a flag of its own (a watermark a user could raise above the fuse would Fatal before it ever spilled).
take_fragment_yielded
Did the last digest_next_body return because of the yield budget (rather than EOF / terminal / depth-drop)? Read-and-clear.
take_implicit_indent
\lastbox at the start of a paragraph begun by a letter or \leavevmode takes its indent box (tex.web §1080), which LaTeXML does not list: the paragraph is then without one, and null if nothing follows (§1096). True when there was one to take.

token_stack_depth

truncate_token_stack

until_body_at_own_level
Whether the open until-body’s own loop reads the next token: no group of the body is open inside it (an unbalanced \abstract{ has its { open), so its terminal ends it without closing one (until_terminal_inside_group).
until_terminal_inside_group
Return the digested List after reading and digesting a body from the its Gullet. The body extends until the current level of boxing or environment is closed. A bounded body’s terminal token (\lx@add@frontmatter@until’s \lx@end@abstract…) invoked INSIDE a group opened within that body — a { group is a nested digest body here (and in Perl, TeX_Box.pool.ltxml: 30-41), so the body’s own loop never sees the token. LaTeX’s rule for an environment end met inside an open group is \@checkend’s “\begin{X} ended by \end{Y}” (latex.ltx:15394) with the groups closed by the error recovery; here the groups above the body are abandoned (abandon_stack_frame: popped, \aftergroup discarded) with a Warning, and the body’s loop is told its terminal arrived (lx@until@terminal@hit). Returns true when it acted. Witness: screenplay-pkg.tex:67 \abstract{…\section — the section then lands at document level, as the brace-less form does.
unwind_box_lists_to
Back to the box lists and boxing depth of mark (box_lists_mark), what was digested since discarded: the lists a failed digestion left suspended (an Err leaves each new_local_box_list it was in unexpired) for a run that is undone (sect05.rs title_page_probe_run).

with_own_adjust_queue
Run f, the digestion of a list of its own whose \vadjust material never reaches the paragraph around it: a restricted horizontal box’s contents (\hbox, \mbox, \sbox, calc’s \widthof, pgfmath’s width()), where it stays in the box and prints nothing (tex.web §655 migrates it only when the packer is handed an adjust list: a paragraph’s lines §889, an alignment’s cells §796), and a \vadjust’s own material, whose paragraph sets what it queued. The list starts with an empty queue and the paragraph’s is put back after (KNOWN_PERL_ERRORS #441; guard box_primitives::vadjust). Residuals: a vertical-mode \hbox (§1076 adjusted_hbox_group) drops it too, where TeX sets it after the box; a tabular’s cells inside the box lose theirs (§799 sets it after the row); hboxes built outside the box reader (\phantom, \text, \resizebox, \underline) keep printing theirs (RED boxes-groups/vadjust_material_stays_in_its_hbox).
with_own_box_list
The current list’s own items, as pop_own_box sees them: in a paragraph only what the paragraph added. What \lastpenalty, \lastkern and \lastskip read (tex.web §424, the tail of the current list) must be what \unpenalty, \unkern and \unskip can remove: reading a vertical penalty from before the paragraph that \unpenalty could not remove looped diagram.sty’s \ifnum\lastpenalty…\unpenalty (2605.02221, 2605.25087). The readers skip is_list_tail_transparent items.
