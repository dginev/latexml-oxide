pub fn copy_provides_refuses_locked(token: &Token) -> bool
Expand description

Does a stand-in’s copy, read or running its hook now (note_copy_provides_assignment), redefine the locked token? Then the lock refuses it as for any file, but keeps no record of it — no \lx@dropped@<name> body for the binding to run in a gap, no <cs>:redefined for it to yield to, no default or signature (the records of a raw class taking over a locked command, OXIDIZED_DESIGN #265, #500): the binding stands in for this very file, so the copy takes nothing over. Logged once per copy, at Info, as a redefinition of an owned name is.
