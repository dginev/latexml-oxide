Constants§

ALIGNMENT_IS_DISPLAY
The alignment property of an alignment that is a display by itself in TeX, $$\halign…$$: amsmath’s align and gather families (amsmath.sty \start@align, \start@gather), latex.ltx’s eqnarray and IEEEtrantools’ IEEEeqnarray (IEEEtrantools.sty:2013). Material a document’s \halign macro typesets before the primitive is an error there (run_halign_redefinition_prelude). Not cases.sty’s numcases, whose \halign is inside a \vbox (cases.sty:73-75). amsmath’s multline is a display too but is not marked: its material is kept in the formula (TeX: “Improper \halign inside $$’s”), the safe direction.
ALIGNMENT_WITHOUT_HALIGN
The alignment property of an alignment set without \halign in TeX: latex.ltx’s tabbing builds each line from boxes (\@startline, \@stopline, \@addfield) and never executes \halign, so a document’s \halign macro does not run for it (run_halign_redefinition_prelude). Every other alignment \lx@begin@alignment starts reaches \halign in TeX.

alignment_to_rule
The alignment whose rows a rule marker (\hline’s \@@alignment@hline, \cline, an \hrule) borders: the current one, except inside a misplaced \noalign’s body, where TeX’s \hrule errors in the cell and draws nothing (tex.web §1126/§1129; see \noalign). A stray \cline/\hline there used to stack border="bbbb…" (2306.10087). Guard: perfect_kernel_batch65::misplaced_hline_in_a_cell_draws_no_rule.
array_strut
The row strut of a LaTeX alignment: \@array builds \@arstrutbox from \strutbox (latex.ltx:16567-16570; the \arraystretch factor is the rowsep attribute), and amsmath’s matrices and cases are \arrays, aligned‘s rows carry \strut@ (amsmath.sty:714-718, :1073-1076, :1121-1126), so a table or matrix nested in a cell, where \baselineskip is zero, keeps its rows’ height. \baselineskip (Perl’s alignmentBindings strut) when \strutbox is void or a class made it something other than a box register (jlreq).
array_zeroes_interline
Whether the LaTeX table being bound zeroes its interline values (latex.ltx:16580 \@array, marking the alignment zero_interline for \lx@begin@alignment). tabularray’s tblr is set as a \tabular/array but builds its own alignment, which keeps them (pdflatex: 12pt in a tblr cell, \\[\baselineskip] a 12pt gap): its mapping marks the next table with \lx@array@keeps@interline, consumed here so a table nested in its cells zeroes again. Repro kernel-alignment/tblr_keeps_its_interline_values.
clear_alignment_row_hooks
A new alignment’s rows run no row hook of an enclosing one: an \halign, {array} or tikzcd in an {eqnarray} or align row inherited \eqnarray@row@before and stepped the equation once per inner row (1601.02132; Perl alike, KNOWN_PERL_ERRORS #518). Every alignment’s bindings call this after assign_alignment; the numbered displays (eqnarray, amsmath, cases) set their hooks afterwards. The hooks are local to the enclosing cell, so the outer alignment’s later rows still run its own.
digest_alignment_body
Digest an alignment’s body, row by row. runs_everycr: the alignment is the \halign primitive’s (tex.web §768-812), which inserts \everycr (insert_everycr) after its preamble and after every row. An alignment a binding builds (\lx@begin@alignment) stands for a LaTeX/plain macro that starts its \halign with an \everycr of its own — \ialign’s \everycr{} (latex.ltx:631, \@array :16573), array.sty’s and longtable’s tagging hooks, amsmath’s \displ@y spacing — whose rows the binding already builds, so it runs none.

report_redefined_span
Report, once per document, that the frozen \span stands in for a redefined one: the document’s \span no longer has the primitive’s command code (is_column_end), so the alignment machinery’s own spans (\multicolumn, \multispan, \sp@n; user ruling 2026-10-11) make a recovery TeX does not make (there the author’s macro runs and the span breaks: “Misplaced \omit”). Witnesses 1405.2652, 0710.0886, math0409364 (\span redefined, \lefteqn’s \multicolumn in eqnarray). Guard: perfect_kernel_batch65::multicolumn_spans_with_the_frozen_span.
restore_dollar_outside_alignment
Gives $ back the meaning it had where the alignment’s bindings ran, once the alignment’s group has closed. \array’s bindings run in the enclosing group, before \@@array opens its own (Perl latex_constructs.pool.ltxml:3755 alike), so without an environment group around it the math-cell $ outlived the array: makecell’s math branch \hbox{$\array…\endarray$} (makecell.sty:131-133) then opened a text box at its closing $ (pdflatex clean; Perl errs too, KNOWN_PERL_ERRORS #462; witness 2606.05500).
