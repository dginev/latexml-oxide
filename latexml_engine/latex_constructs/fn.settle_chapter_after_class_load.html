pub fn settle_chapter_after_class_load() -> Result<()>

OXIDIZED_DESIGN #179, the “has chapters” step, after each class load of a \documentclass document: the class’s own (\documentclass), a raw class’s \LoadClass/\LoadClassWithOptions (sect05.rs), a binding’s LoadClass! (setup_binding_language.rs) and a runtime script binding’s LoadClass (latexml_contrib script_bindings/engine.rs; guard perfect_kernel_batch72b::a_script_binding_class_load_settles_the_chapters). It makes the one “has chapters” test (state::class_has_chapters_now: (a) the class’s own code assigned \chapter, (b) a compiled binding made \c@chapter, (c) OmniBus guesses an unknown class) and stores its answer for state::class_defines_chapter — natbib’s forks, appendix.sty, titlesec.sty and the kernel’s \appendix read it. Where the class has chapters by (b) or (c) and \chapter is undefined, the kernel’s is put back, locked (a report-based binding’s later code and packages see it); where it has none, \chapter is left undefined and unlocked, so every \@ifundefined{chapter} a class or package makes gets TeX’s answer: the raw natbib forks under bmvc2k (bmvc2k_natbib.sty:779) and WileyNJD (NJDnatbib.sty:1050) took the \chapter*{\bibname} branch (2412.14509, 2212.00057, 2210.06270, 1501.07873, 2311.17607, 2406.08486; 2101.06297, 2211.16474, 2411.11493, 2206.08798, 2602.03829, 2408.07575, 2609.08425, 2506.14995), blindtext’s \blinddocument made a chapter (blindtext.sty:243, hvfloat’s test documents, coseoul, xassoccnt), and a class body’s probe after its \LoadClass{article} (aguplus.cls:524 “figcaps may only be used with article-like classes”) saw article’s answer. A class that builds its own chapters afterwards (source3body.tex:100-123 \newcounter{chapter} + \newcommand\chapter) is not “Ignoring redefinition of \chapter” (KNOWN_PERL_ERRORS #141). A document that calls \chapter all the same gets LaTeXML’s chapter with one Warning (OXIDIZED_DESIGN #734, \lx@chapterless@chapter). Its own removal is no assignment of a stand-in’s copy: a copy’s \LoadClass (tlp) settles outside the copy’s provides-mode. Guards: perfect_kernel_batch56::loadclass_return_retracts_kernel_chapter, perfect_kernel_batch72b::chapter_exists_where_the_class_has_chapters, perfect_kernel_batch72b::a_class_has_chapters_when_its_code_defines_chapter.
