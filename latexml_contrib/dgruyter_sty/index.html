dgruyter.sty (De Gruyter’s journal style, shipped by the papers that use it; not in TeX Live) — a stand-in: the paper’s copy is read after it (“a stand-in’s copy provides”, OXIDIZED_DESIGN_DIVERGENCES #731), so the copy’s definitions of names the kernel’s semantic layer or this binding owns hold only inside its own code — its copy of array.sty’s \@array (dgruyter.sty:2003-2029, calling array.sty’s \@arrayleft), its \let\@@array\@array (:2031) and \@@array, \@tabular, \@classz, \endtabular wrappers (:2032-2056) — and the document’s alignments stay the native ones, while the copy’s extras stand as it makes them. Read raw with no binding (the ar5iv preload reads a shipped style that has none), the copy’s array code took over every array: 2510.17333’s bordered block matrices, 274 errors and two section labels lost; 2301.07931 101 errors and a Fatal. Guard perfect_kernel_batch80a::dgruyter_copy_keeps_the_native_array.

The copy’s \maketitle is the kernel’s too, so the frontmatter dgruyter stores for its title page (:2665-2760: \subtitle, \keywords, \classification, the history dates, \communicated, \dedication, \DOI) is declared here as the frontmatter’s elements; the running heads and the journal’s issue data are page furniture. Guard perfect_kernel_batch80a::dgruyter_frontmatter_is_kept.
