XML/HTML output sink — port of LaTeXML::Post::Writer.

Two related concerns live here:

  1. The Writer post-processor (last in the chain) that serializes a PostDocument to its destination, handling DOCTYPE removal, TEMPORARY_DOCUMENT_ID cleanup, and HTML vs XML serialization.
  2. Free-standing helpers (write_output, ensure_parent_dir) used by binary main()s that already have the serialized string in hand (post-processing returns a String) and need to route it to a destination path or stdout. Replaces the duplicated File::create + write! + ensure_parent_dir boilerplate that used to live in latexml_oxide.rs (and the now-retired latexmlpost_oxide.rs).

Companion module: crate::pack (the LaTeXML::Post::Pack analog) handles archive bundling when the destination is a zip.

MadeDirs
The directories a page render already made: a split run writes thousands of pages into a handful of directories, and each create_dir_all is a mkdir and a statx (Nasser’s 71,476-page document, #777 FAQ).
Staged
A private file beside a destination that parallel render workers may share (the CSS, a figure every page uses): written or converted there, then installed by one rename, so no reader sees a partial file and no writer touches another’s. Named .<stem>.tmp.<pid>.<seq>.<ext> (the stem bounded), its extension kept last for converters that read the format from it; registered with the watchdog’s exit sweep, and removed when dropped — after an install too, since a rename onto a hard link of the same file succeeds and leaves both names (POSIX rename(2); a graphics-cache entry linked into the destination by a sibling worker). A name some file already holds — a killed run’s leftover, perhaps a link to a cache entry, or a process with the same pid in another PID namespace sharing the cache — is skipped, never written through.

Like write_output but writes several segments back-to-back without concatenating them into one buffer first.
