axodraw.sty — J.A.M. Vermaseren’s Feynman-diagram package, version 1 (“Made by J.A.M. Vermaseren 14-feb-1994”).

axodraw v1 is neither in TeX Live (which has its successor axodraw2) nor, mostly, shipped with the papers that load it: run 336 had 1,507 arXiv papers with \Text undefined (149 as their first error; witnesses hep-th0506235, hep-ph0512261, hep-ph0305218, 0710.3255, 0809.0800). Its drawing layer is PostScript: every command is \put(\axoxoff,\axoyoff) around a \special{"…} that calls a procedure the package installs with \special{! …} (dvips header code), so a raw load draws nothing even where the file is present. This binding keeps v1’s TeX layer — the same command signatures, \Set* state macros and \put placement — and replaces each \special with \lx@axo@draw{procedure}{arguments}, which evaluates the procedure’s geometry here, transcribed from the v1 PostScript, into the picture model (ltx:line, ltx:bezier, ltx:arc, ltx:circle, ltx:polygon, ltx:rect, ltx:ellipse) that {picture} and the pstricks binding emit and the SVG post-processor renders.

A paper’s own copy of axodraw.sty (about one zip in 830 ships one) is answered by this binding too, as any binding outranks a raw file: raw, its drawing is lost all the same. axodraw2 (TeX Live) and axodraw4j (JaxoDraw’s 2008 keyval forerunner of axodraw2, shipped by papers: 1301.5845, 1701.08134) are other packages, read from their files (axodraw2_sty.rs keeps the versioned-name fallback off axodraw2).

An argument is what v1 splices into PostScript, so it may be a PostScript expression over a dvips-header constant ({20 Tdensity mul}, 0901.1195, 1701.01554): ps_value evaluates the arithmetic.

The command set is the union of the v1 variants arXiv papers ship (all share one PostScript geometry): the original 1994 file (hep-ph9702393, hep-ph0101185) and the colordvi-aware one adding \SetColor, \CCirc, \CBox(c), \COval, \CText, \C2Text and the triangles (hep-ph0101235).

Units, v1 semantics (both sides deliberate in v1, and relied on by papers: 0809.0800 writes \unitlength 0.6pt\SetScale{0.6}): graphics coordinates are PostScript points scaled by \SetScale and ignore \unitlength; \Text/\rText place TeX text at \unitlength multiples, unscaled. v1 draws in big points; this reads them as TeX points, the correction axodraw2 made (axodraw2.sty:3080 /gs{gsave 1.00375 div dup scale}), so a label set at the same coordinates as a line meets it.
