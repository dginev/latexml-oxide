No-op stub for constants.sty.

constants.sty (TL — “Labeling and numbering constants”) provides \newconstantfamily, \C, \Cl, \refconstant, \resetconstant. Its end-of-document bookkeeping (constants.sty L143-148) does a raw \if@filesw … \makeatletter \input\jobname.aux \fi to re-read the label .aux for the “constants may have changed, rerun” check.

Until \begin{document} opened \jobname.aux (sect02.rs, OXIDIZED_DESIGN #576), no in-memory <jobname>.aux existed and that raw \input\jobname.aux failed with Error:missing_file:<jobname>.aux (constants.sty uses the hard \input, not LaTeX’s silent \@input). The re-read stays out of the port: there is no .aux round trip to check (see below).

Perl LaTeXML never observes this: its default TEXINPUTS excludes /usr/share/texlive, so constants.sty is reported missing-file and skipped — providing ZERO constants functionality. Verified on arXiv:2002.05335: Perl emits Warning:missing_file:constants and completes (its residual errors are unrelated math-mode issues).

The package is ported whole except that end-of-document re-read: \Cl{<label>} records its constant at once (where constants.sty writes \newlabelconstant to the .aux for the next run), so \Cr{<label>} after it gives the constant and a forward one the “??” and warning of LaTeX’s first run. Run 340: \Cr was the first error of 253 papers under the former no-op stub, which also dropped every \C’s C_n (2508.09984, 2103.05634, 2508.14888). The \null closing each \@set…constant branch (an empty box, ending the number or name the \expandafter produced) is \relax here, which ends it the same way without an empty box in the formula.

Witnesses (CONVERR_1 → OK): 2004.04403, 2002.05335, 1501.05396, 1503.01423, 1505.03199, 1506.02544, 1506.03382, 1506.03705, 1508.03002, 1509.02505, 1512.06906, 1601.01096, 1603.05947, 1606.09238, … (70 total).
