amsmath for a binding whose original file does not load it — spie.cls (TeX Live’s; spieman.cls), the old ws-procs9x6.cls and ws-ijmpb.cls copies, Scientific Word 2.5’s tcilatex.tex, OmniBus’s autoload, the old aa.cls — so that a paper using amsmath’s commands without loading it still gets them (original_loads: the original does load it, as the paper’s copy reads, crate::shipped_class::shipped_copy_loads; then this is the plain load), with the options the original passes to it (imsart.cls:84-118 \PassOptionsToPackage{leqno}{amsmath}). In pdflatex amsmath is not loaded there: a \pmatrix{…}, \matrix{…} or \cases{…} is Plain TeX’s, with no “Old form \pmatrix'" error (amsmath.sty:1077-1090 \matrix@check), and @ifpackageloaded{amsmath} is false (0805.4522 tcilatex, 1003.3524 spie, nucl-th0206027 ws-procs9x6, quant-ph0607049 ws-ijmpb: no error in pdflatex). So the old-form error is off ([amsmath_loaded_beyond_original]) until the real amsmath.sty loads: the document's own \usepackage{amsmath}, a raw class or package that loads it (ptptex.cls:362 \if@ams; a copy's own load, read as the stand-in's copy, binding::author_files), or a binding whose original does (mathtools, physics). That load runs the binding again, its \matrix@errorthe error again, as Perl's aa.cls.ltxml:57 reload does for aa. A second such binding finds amsmath's definitions in force and loads nothing. Guardsperfect_kernel_batch77q::{old_form_matrix_is_plain_tex_where_amsmath_is_not_loaded, old_form_matrix_errs_once_the_document_loads_amsmath}`.
