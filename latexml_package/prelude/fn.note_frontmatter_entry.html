The frontmatter API queues an entry tag of role role (queue.rs queue_front_matter, its invocation command; \lx@add@frontmatter@until, none): when it is made inside the calls of LaTeXML’s own macros that read their arguments from the document’s own text (state::claim_open_document_calls, noted by Expandable::invoke), those are the document’s frontmatter commands, and what TeX makes of what it gave them is wanted in the output as the title page’s print is — a binding’s \maketitle has no print run (daj, elsarticle, aastex: their bindings write the frontmatter), and a binding’s command may drop what pdflatex prints. TeX settles every shape: the entry’s own digested content is read when it is digested (end_frontmatter_entry_digestion, by ink_word_text as the print is), and an argument no entry digests (never_digested, or one a binding’s macro drops while the entry is digested) is digested once then, speculatively. The record’s number, for an entry digested where it stands. What the binding declares is what it places: a command it only stores (a running head’s \def\@shorttitle{…}, a field its class never prints) queues nothing and is no frontmatter command; nor is a running head the API holds as one (ltx:toctitle). Not after the authors are sealed (a supplement’s), nor after the title page was made (but an entry printed where it stands, an abstract), nor while a raw class’s setter replays, a speculative run digests or a stand-in copy is read.
