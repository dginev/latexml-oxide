pub fn standard_class_binding_name(token: &Token) -> bool
Expand description

Is token a text name the standard class’s binding assigned in its own load, which a derivative of that class read now defines itself (binding::content::standard_class_binding_assigned, OXIDIZED_DESIGN_DIVERGENCES #731 rule 13)? In TeX the derivative is read in the class’s place, so its \newcommand of the name is the first: aip-cp.cls:875 \newcommand\refname{REFERENCES} (1506.04050, 1604.08112). Only a declared text name yields (copy_text_name_declared: \refname, \figurename, \abstractname); every other name the binding defined stays its markup of the class — \appendix (<ltx:appendix>, article_cls.rs, book_cls.rs), book’s \frontmatter/\mainmatter/\backmatter (unnumbered chapters), whose \newcommands in a full class copy (hep-ex0405054’s book_modified.cls:531, math0301023’s khbook.cls:285; 0705.2210, hep-ph0008011, cond-mat0402505, quant-ph0409078) lost the appendices and numbered the preface; the caption formats (\fnum@table), \@ptsize, \@pnumwidth. Names a stand-in the derivative loads assigned are not the class’s (guard perfect_kernel_batch77w::standard_class_derivative_defines_only_its_class_names).
