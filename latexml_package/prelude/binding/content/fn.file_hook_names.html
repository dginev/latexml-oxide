latex.ltx:19646-19673 \InputIfFileExists, around a content file LaTeX’s \input{…} reads (\@iinput; TeX’s \@@input runs no hooks): the file’s names are pushed on ltfilehook’s stack and set (\CurrentFile, \CurrentFilePath and their Used twins), file/before and file/<name>/before run, the file is read, its names are set again for file/<name>/after and file/after, and the stack pops back to the enclosing file’s. The hooks run where the file’s tokens are read — the before part ahead of them in the file’s own input level, the after part after them in the enclosing one — since \input expands. Package and class loads run the same hooks (use_load_hooks). Perl fires none (Package.pm Input), so filehook’s file/before code never ran and currfile’s \currfiledir stayed the main file’s inside an \input file: 2110.08325’s \edef\path{\currfiledir} + \input{\path/settings} read /settings (missing; its TikZ figures undefined). The assignment of a file’s names (\CurrentFile, \CurrentFilePath and their Used twins) for request, and its name: \__filehook_file_parse_full_name:nN, the directory without its last /, the name with .tex when the request has no extension.
