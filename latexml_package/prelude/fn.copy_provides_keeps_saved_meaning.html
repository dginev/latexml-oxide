Expand description

Does a stand-in’s copy, read now (note_copy_provides_assignment), save source again into token — \let \token\source — where token already holds an earlier meaning of source (its definition is a \let copy made under source’s name, definition_cs) that the stand-in binding’s load assigned, and source has been redefined since — by the binding, the copy’s read not having assigned source itself — to a meaning that reaches token (meaning_reaches), so that the \let would make it call itself? Then the \let is declined, in the copy’s code too: token keeps the meaning TeX gives it, source before the redefinition. The binding (or a file it read) made the very save-and-wrap the copy makes — \let\org\X, then \X redefined to call \org —, and saving the wrapper into \org makes \X call itself: myjmlr.cls and jmlr_mod.cls (renamed jmlr.cls copies routed to the jmlr binding, whose jmlrutils.sty made the same wrap) run \let\jmlr@org@newtheorem\newtheorem (jmlr.cls:753-754) before their own \newtheorem{example}, which looped to the timeout (1506.02582, 2304.14217; OXIDIZED_DESIGN_DIVERGENCES #731 rule 2, the epl2.cls \let\epl@org@bibitem case met in the copy’s own code). Logged once per copy, at Info.
