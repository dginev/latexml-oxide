1//! tikzlibraryexternal.code.tex — TikZ picture externalization.
2//!
3//! The real library is loaded; only its operating MODE is changed. With
4//! `\tikzexternalize` in its default `convert with system call` mode every
5//! `tikzpicture` is intercepted, the external file is absent, the shell
6//! escape (`\write18`, inert here) yields nothing, and
7//! tikzexternalshared.code.tex:1636 raises "the system call … did NOT
8//! result in a usable output file" — then typesets the picture inline
9//! anyway. TeX Live builds these manuals with `-shell-escape`; a plain run
10//! and Perl LaTeXML raise the same error per picture (tikzviolinplots 591,
11//! causets 106, tilings 80, tikz-feynhand 55, tikzscale 5). tikz's own
12//! `mode=graphics if exists` (tikzexternalshared.code.tex:137) is the
13//! faithful no-shell-escape behaviour: use the graphics file when present,
14//! otherwise typeset inline with no system call. Guard:
15//! `perfect_kernel_batch56::tikz_externalize_typesets_inline_without_a_system_call`.
16use crate::prelude::*;
17
18LoadDefinitions!({
19  InputDefinitions!(
20    "tikzlibraryexternal.code",
21    extension => Some(Cow::Borrowed("tex")),
22    noltxml => true
23  );
24  RawTeX!(r"\tikzset{/tikz/external/mode=graphics if exists}");
25});
