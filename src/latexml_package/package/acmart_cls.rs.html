87  NewCounter!("acmlabel", "");
88  // `\Description[short]{long}` — acmart's accessible figure description
89  // (acmart.cls L895 gobbles both args; ACM requires the description, and HTML
90  // can carry it where PDF cannot, so we surface it rather than follow the
91  // class into discarding it).
92  //
93  // The MANDATORY long description is the real alt text, so it is what we
94  // emit. It is read `Undigested` — `ExpansionLevel::Off`, kept as
95  // `DigestedData::Postponed` tokens — so nothing inside it expands: the
96  // author never sees a defect there under pdflatex (the class gobbles it), so
97  // expanding it only manufactures errors. Witness arXiv:2607.21760, whose
98  // `\D1 … \D5` (a copy-paste slip from the adjacent `alt=` text, which has
99  // plain `D1 … D5`) raised `Error:undefined:\D` for content we then dropped.
100  //
101  // `LaTeXML-common.xsl` L404-421 maps any `aria:*` attribute to `aria-*`
102  // under HTML5, so setting them here needs no XSLT change. Which ARIA slot
103  // each argument lands in is the `before_construct` table below.
104  //
105  // `[short]` and `{long}` are two DISTINCT authored fields, so they get two
106  // distinct elements — never concatenated into one. Merging them yields a
107  // run-on ("Fly 1 and Fly 2 look identical. Fly 1 and fly 2 comparison
108  // shows…") and destroys the distinction, so no consumer can tell which text
109  // the author wrote as the brief alternative.
110  //
111  // The old binding emitted the short one ALONE, which is why
112  // `t/complex/acm_aria` recorded "Fly 1 and Fly 2 look identical" and lost the
113  // sentence that actually describes the figure.
114  //
115  // Carried as `<ltx:note>` — the document builder places a note inside the
116  // float's `<caption>`, where the old binding put it. An `<ltx:text>` is
117  // INLINE, so the builder auto-opens a `<p>` for it, and a `<p>` at figure
118  // level is tagged `ltx_figure_panel`, which makes the post-processor spin up
119  // a whole `ltx_flex_figure`/`ltx_flex_cell` wrapper around two hidden spans
120  // (inert, since the caption partitions it and the real subfigures keep their
121  // width class, but pure noise in the output).
122  //
123  // The footnote decoration a note normally gets — the `†` mark and the
124  // `<role>: ` type prefix — is suppressed for these by a dedicated template in
125  // `LaTeXML-meta-xhtml.xsl` keyed on `ltx_acm_description`, so the referenced
126  // text stays clean for assistive technology.
127  //
128  // The short description gets its own id so it stays individually
129  // addressable (nothing references it today — its text goes into
130  // `aria-label` — but an anchor on authored content costs nothing). It is
131  // derived in `properties` rather than written as `#id-short` in the
132  // template, which does NOT work: a `#name` hole runs to the end of the
133  // identifier, so `#id-short` names a property called `id-short` — absent,
134  // so the element silently emits NO xml:id at all — instead of `#id`
135  // followed by a literal `-short`. Ids use a `-short` suffix rather than a
136  // dotted one so they need no escaping in a CSS selector.
137  DefConstructor!("\\Description[] Undigested",
138    "^^?#1(<ltx:note xml:id='#shortid' class='ltx_nodisplay ltx_acm_description_short'>#1</ltx:note>)()\
139     <ltx:note xml:id='#id' class='ltx_nodisplay ltx_acm_description'>#2</ltx:note>",
140    properties => {
141      let mut props = RefStepCounter!("acmlabel")?;
142      if let Some(id) = props.get("id") {
143        let short = format!("{id}-short");
144        props.insert("shortid", Stored::from(short));
145      }
146      // Perl acmart.cls.ltxml L79 sets these so the hidden note claims no
147      // layout space; carried over.
148      props.insert("width", Stored::from(Dimension!("0pt")));
149      props.insert("height", Stored::from(Dimension!("0pt")));
150      Ok(props)
151    },
152    // acmart's own documentation: "Unlike \caption, which is used alongside the
153    // image, \Description is intended to be used INSTEAD OF the image." So a
154    // `\Description` is a TEXT ALTERNATIVE, not supplementary prose — which in
155    // ARIA is name-like (`aria-label`), not `aria-describedby` (announced in
156    // ADDITION to the name). That also fixes the two arguments' roles: `[short]`
157    // is the concise alternative, `{long}` the extended description.
158    //
159    //   `\Description[s]{l}`  → aria-label = s, aria-describedby → l's block
160    //   `\Description{l}`, l plain    → aria-label = l (it replaces the image)
161    //   `\Description{l}`, l w/ markup → aria-describedby → l's block
162    //
163    // The last case is why the argument is read `Undigested`: an `aria-label`
164    // is a plain string and cannot carry markup, so we must inspect the tokens
165    // to choose the slot BEFORE expanding anything. A control sequence (or an
166    // active/`$`/`^`/`_` token) means real markup, so the block carries it.
167    //
168    // The block is always emitted, so the text stays addressable, but it is
169    // referenced only when it is not already the label — otherwise the same
170    // sentence would be both the name and the description. An unreferenced
171    // hidden block is inert: `display:none` content is announced only when
172    // something references it.
173    //
174    // acmart's NEW mechanism for the same purpose is `\includegraphics[alt=…]`
175    // (switched on by `\DocumentMetadata`), handled in `graphicx_sty.rs` and
176    // landing on the `<img>` itself. A document using BOTH — e.g.
177    // arXiv:2607.21760, which repeats the same paragraph in each — will convey
178    // it twice; that is the author's duplication across two documented
179    // mechanisms, not something to second-guess here, and `\Description` is
180    // scoped to the float with no reliable way to associate it with one image.
181    before_construct => sub[document, whatsit] {
182      let Some(id) = whatsit.get_property("id").map(|v| v.to_string()) else {
183        return Ok(());
184      };
185      // Does the long description contain markup, or is it plain text?
186      let long_is_plain = whatsit
187        .get_arg(2)
188        .and_then(|d| d.raw_tokens())
189        .is_some_and(|tks| {
190          tks.unlist_ref().iter().all(|t| {
191            matches!(
192              t.get_catcode(),
193              Catcode::LETTER | Catcode::OTHER | Catcode::SPACE | Catcode::EOL
194            )
195          })
196        });
197      let short = whatsit.get_arg(1).map(|d| d.to_attribute());
198      let Some(mut figure) = document.get_element() else {
199        return Ok(());
200      };
201      match short {
202        // Concise alternative available: it labels, the long one describes.
203        Some(s) => {
204          document.set_attribute(&mut figure, "aria:label", &s)?;
205          document.set_attribute(&mut figure, "aria:describedby", &id)?;
206        },
207        // Lone description: it stands in for the image, so it labels — unless
208        // it carries markup an attribute cannot hold.
209        None if long_is_plain => {
210          let text = whatsit.get_arg(2).map(|d| d.to_attribute()).unwrap_or_default();
211          document.set_attribute(&mut figure, "aria:label", &text)?;
212        },
213        None => {
214          document.set_attribute(&mut figure, "aria:describedby", &id)?;
215        },
216      }
217    }
218  );

317  // Float environments
318  //
319  // teaserfigure — real acmart DEFERS the teaser: `\newenvironment{teaserfigure}
320  // {\Collect@Body\@saveteaser}{}` (cls L2202) stashes the body into
321  // `\@teaserfigures`, and `\maketitle` renders it via `\@mkteasers` (cls L2240,
322  // L2899) as the last part of the top-matter box — so in the PDF the teaser
323  // appears AFTER the title+authors and BEFORE the abstract, not where the
324  // environment is written (typically before `\maketitle`). Perl LaTeXML has no
325  // teaserfigure binding at all, so any handling here is beyond-Perl.
326  //
327  // We DIGEST + CONSTRUCT the teaser in place (below) so `\label`/`\ref`,
328  // `\caption` numbering, `xml:id` and `inlist` all resolve exactly as for a
329  // normal float — the teaser in arXiv 2606.22880 is `\ref`-ed 6+ times, so the
330  // figure node must own the label. The prior inline result merely landed in the
331  // wrong PLACE (first `<document>` child, ahead of the title, because the env is
332  // written before `\maketitle`). The `\lx@relocate@teaser` DOCUMENT_REWRITE rule
333  // registered just below moves the finished node to just before the abstract
334  // (user-directed 2026-07-13 — timing/position of `\maketitle`, no frontmatter
335  // markup added over the figure).
336  DefEnvironment!("{teaserfigure}[]",
337    "<ltx:figure xml:id='#id' inlist='#inlist' class='ltx_teaserfigure' ?#1(placement='#1')>#tags#body</ltx:figure>",
338    before_digest => { before_float("figure", None); },
339    after_digest => sub[whatsit] { after_float(whatsit); },
340    mode => "internal_vertical"
341  );
342  // Relocate the constructed teaser to acmart's top-matter position: immediately
343  // before the abstract (PDF order: title, authors, teaser, abstract). Runs as a
344  // post-construction DOM rewrite so the figure keeps its id/label/number — only
345  // its position changes.
346  //
347  // We anchor on the ABSTRACT, not the teaser: the rewrite `replace` engine
348  // unbinds the matched node AND every FOLLOWING sibling (re-appending them after
349  // the closure), so matching the teaser — the first `<document>` child — would
350  // detach the whole frontmatter and leave the teaser stuck at the front. The
351  // abstract's PRECEDING siblings (the teaser, title, creators) stay bound, so we
352  // move the still-bound teaser to just before the re-attached abstract. The
353  // xpath predicate gates the rule to teaser-bearing documents only, so a plain
354  // acmart abstract is untouched.
355  DefRewrite!(
356    xpath => "//ltx:abstract[//ltx:figure[contains(@class,'ltx_teaserfigure')]]",
357    replace => sub[document, nodes] {
358      let abs = nodes.pop().unwrap();
359      // Re-attach the abstract at its original parent (the rewrite engine set the
360      // current node to that parent before calling us).
361      document.get_node_mut().add_child(abs)?;
362      // Move the still-bound teaser to just before the abstract.
363      let teasers =
364        document.findnodes("//ltx:figure[contains(@class,'ltx_teaserfigure')]", None);
365      if let Some(mut teaser) = teasers.into_iter().next() {
366        abs.add_prev_sibling(&mut teaser)?;
367      }
368    });
