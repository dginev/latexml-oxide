1//! xpatch.sty — etoolbox patching that also reaches robust/`\protect`ed commands.
2//!
3//! **Why a native binding.** xpatch is an expl3 package: every public command is
4//! a `\NewDocumentCommand` dispatching to `\xpatch_main:NN`, which stringifies the
5//! target with `\cs_replacement_spec:N` and then re-reads the body delimited by a
6//! sentinel token list, `\c__xpatch_bizarre_tl` = `**)-(**/**]-[**`. Raw-loading
7//! it makes that delimited scan run to end-of-file, so **everything after the
8//! first `\xpatchcmd` is silently discarded** — no error, no output.
9//!
10//! Witness **2605.25157**: `\xpatchcmd{\@tocline}…` in the preamble; the paper's
11//! own `\begin{thebibliography}` with 33 `\bibitem`s never digested, and the
12//! document was truncated mid-proof at line 1292 of 1749 with **zero** errors
13//! reported. Perl truncates identically, but at least raises
14//! `Error:expected:Until:**)-(**/**]-[**` twice — our silence was strictly worse.
15//! 10 papers in the 2605+2606 bibliography-absence residual load xpatch.
16//!
17//! **Why the mapping is this simple.** xpatch exists to pierce one indirection:
18//! a command declared `\DeclareRobustCommand`/`\newrobustcmd` keeps its body in
19//! `\<name><space>`, which etoolbox's `\patchcmd` cannot see. **That indirection
20//! does not exist here** — `latex_base.rs`'s `\DeclareRobustCommand` marks the
21//! macro itself `robust => true` (as does etoolbox's `\newrobustcmd`), so there
22//! is no inner macro to redirect to and each `\x…` command is exactly its
23//! etoolbox counterpart applied to the same derived control-sequence name.
24//! `\patchcmd` already reports a native-definition target with an `Info`, so the
25//! failure mode is a diagnostic rather than a runaway.
26//!
27//! Perl has no xpatch binding, so this is surpass-Perl; ground truth is the arXiv
28//! PDF. Audit `docs/parity/BIB_ABSENCE_AUDIT_2026-07-29.md`.
