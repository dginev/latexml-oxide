6  // a simplification that drops the real package's entire effect, so both
7  // engines leave the first-line indent that `\usepackage{parskip}` is meant to
8  // remove (issue #558, reporter nasser1; same-host Perl 0.8.8 identical =>
9  // SHARED-FAILURE). Ground truth is the real package, so load it raw —
10  // surpass-Perl, OXIDIZED_DESIGN #106. parskip.sty v2.0h (2021-03-14):
11  //  * requires kvoptions (L44) and processes its `indent`/`parfill`/`skip`/
12  //    `tocskip` options (L45-50), then sets `\parskip` (L51-55, default
13  //    `.5\baselineskip plus 2pt`), `\parfillskip` (L56-57) and `\parindent`
14  //    (L58, default `indent=0pt`);
15  //  * requires etoolbox (L59) for its `\patchcmd`s, which the document may use
16  //    too: loading neither left `\AtEndPreamble` undefined wherever etoolbox
17  //    did not arrive by another route (under pdfTeX it came only through babel;
18  //    witnesses liftarm, polyomino under the `[luatex]` profile).
19  //    Guard: `shipout_parskip::parskip_loads_kvoptions_and_etoolbox`.
20  //
21  // `\parindent=0` is the whole fix for the reported symptom: the paragraph
22  // machinery flips every paragraph to the `ltx_noindent` class when the
23  // `\parindent` register is zero (`tex_paragraph.rs`, the boolean no-indent
24  // toggle), exactly as a manual `\setlength{\parindent}{0pt}` already does.
25  // The FIRST paragraph joined this only with issue #719 (same reporter): the
26  // deferred `\par` mechanism records the class for the NEXT paragraph, so
27  // before #719 the first paragraph kept the stylesheet's default indent.
28  // Guarded by `parskip_test` (all three paragraphs now `ltx_noindent`).
29  // `\parskip` is set for faithfulness to the real package (its glue is not
30  // typeset into HTML by LaTeXML — neither here nor for a manual `\setlength`).
31  // Expected on every parskip document: parskip's `\patchcmd\@startsection`
32  // fails (LaTeXML's `\@startsection` has no `\addvspace\@tempskipa`), giving
33  // one `Info:unexpected:patchcmd` and the console line "Couldn't patch
34  // \@startsection"; its `\@starttoc` and `\@xsect` patches apply. The spacing
35  // it patches never reaches the XML, so neither message needs a fix.
