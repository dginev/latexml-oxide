4LoadDefinitions!({
5  // Perl `parskip.sty.ltxml` is an EMPTY stub ("Nothing to do here, really") —
6  // a simplification that drops the real package's entire effect, so both
7  // engines leave the first-line indent that `\usepackage{parskip}` is meant to
8  // remove (issue #558, reporter nasser1; same-host Perl 0.8.8 identical =>
9  // SHARED-FAILURE). Ground truth is the real package: parskip.sty v2.0h sets
10  // `\setlength\parindent{0pt}` (L58, default `indent=0pt`) and
11  // `\parskip=.5\baselineskip plus 2pt` (L51-54). Port that here — surpass-Perl,
12  // OXIDIZED_DESIGN #106.
13  //
14  // `\parindent=0` is the whole fix for the reported symptom: the paragraph
15  // machinery flips every paragraph to the `ltx_noindent` class when the
16  // `\parindent` register is zero (`tex_paragraph.rs`, the boolean no-indent
17  // toggle), exactly as a manual `\setlength{\parindent}{0pt}` already does.
18  // The FIRST paragraph joined this only with issue #719 (same reporter): the
19  // deferred `\par` mechanism records the class for the NEXT paragraph, so
20  // before #719 the first paragraph kept the stylesheet's default indent.
21  // Guarded by `parskip_test` (all three paragraphs now `ltx_noindent`).
22  // `\parskip` is set for faithfulness to the real package (its glue is not
23  // typeset into HTML by LaTeXML — neither here nor for a manual `\setlength`).
24  //
25  // Package options (`skip`/`indent`/`tocskip`, kvoptions) are not yet handled;
26  // the no-option `\usepackage{parskip}` default is the common case (and the one
27  // reported).
28  RawTeX!(r"\setlength{\parindent}{0pt}\setlength{\parskip}{.5\baselineskip plus 2pt}");
29});
