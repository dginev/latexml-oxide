1//! codehigh.sty — raw load, with the LuaTeX code parser degraded to plain
2//! (unhighlighted) text.
3//!
4//! codehigh.sty:508 dispatches on `\legacy_if:nTF {LuaTeX}`: under the
5//! `luatex` profile it takes `\__cdhh_parse_code_luatex:nN` (:575-586), whose
6//! `\directlua{ParseCode(token.scan_argument(),…)}` needs the LuaTeX runtime
7//! `token` library our texlua bridge cannot supply, so the Lua-defined
8//! `\l__cdhh_parse_code_count_tl` never existed (CreationBoites-doc,
9//! tkz-bernoulli-doc, tabularray-abnt-pt-br, functional). Pinning the
10//! l3regex parser (:514) instead highlighted correctly but is O(n²) in the
11//! code length (PLANS P65) — all four manuals ran past the 300 s sweep
12//! timeout (sweep #34). So the LuaTeX path typesets the code as one
13//! unstyled chunk (style `0`, what the normal parser emits for non-matching
14//! text): the listing is kept verbatim, without colour, in bounded time. The
15//! non-LuaTeX parser (`\__cdhh_parse_code_normal:nN`, codehigh.sty:514-570:
16//! `\bool_do_until` re-running `\regex_extract_once`/`\regex_split` on the
17//! whole remaining code per rule) has the same O(rules·n²) shape, so
18//! `\dochighinput{<package>.sty}` of a 1000-line source (fontscale-code,
19//! scaletextbullet-code, polyomino, pegmatch, liftarm, broydensolve-doc,
20//! codehigh's own manual — measured 3 s load, 65 s for 60 lines, timeout at
21//! 200) ran past every limit; it degrades the same way. pdflatex is fast and
22//! clean; Perl raw-loads the same regex engine and times out too. Guard:
23//! `perfect_kernel_batch56::codehigh_dochighinput_is_bounded`.
24use crate::prelude::*;
25
26LoadDefinitions!({
27  InputDefinitions!("codehigh", noltxml => true, extension => Some(Cow::Borrowed("sty")));
28  RawTeX!(
29    r"\ExplSyntaxOn
30\cs_set_protected:Npn \__cdhh_parse_code_luatex:nN #1 #2 { \__cdhh_typeset_text:nN {0} #2 }
31\cs_set_protected:Npn \__cdhh_parse_code_normal:nN #1 #2 { \__cdhh_typeset_text:nN {0} #2 }
32\ExplSyntaxOff"
33  );
34});
