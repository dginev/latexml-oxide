1//! geometry.sty — page layout.
2//!
3//! Perl LaTeXML (`geometry.sty.ltxml`) makes every geometry macro a no-op:
4//! page geometry is meaningless for the reflowable HTML body, so `\textwidth`
5//! stays at the class default (345pt). We keep that behaviour for the HTML flow
6//! — a `\rule{0.5\linewidth}`, a text minipage, `\includegraphics[width=
7//! \linewidth]` etc. are all sized from the class default exactly as in Perl.
8//!
9//! **Divergence from Perl (OXIDIZED_DESIGN #99):** a *measured SVG graphic*
10//! that reads `\linewidth` — a `tcolorbox`, `tikzpicture`, or bare `pgfpicture`
11//! — is emitted as a fixed-size `<svg>` whose aspect ratio is baked at
12//! conversion time, so ignoring the real page width there makes the picture
13//! `0.5 x 345pt` instead of the `0.5 x 472pt` the PDF draws (letterpaper minus
14//! the document's margins). The narrow interior over-wraps the content, roughly
15//! doubling the box height and pushing text through the border
16//! (arXiv:2605.29955, Figure 1). So we DO compute the geometry text width/height
17//! and inject it into `\linewidth`/`\hsize`/`\columnwidth`/`\textwidth` — but
18//! ONLY inside SVG-producing pictures, never into the main HTML flow. The guard
19//! `\ifdim\linewidth=\textwidth` applies it only at the top level, leaving a
20//! locally-reduced `\linewidth` (nested minipage/parbox) alone.

121%% ---- SVG-scope injection -------------------------------------------------
122% Applied at the start of an SVG-producing picture: raise \linewidth (and the
123% siblings measured graphics read) to the geometry text width, but ONLY when the
124% picture is at the FULL column width — compared against the class-default
125% \textwidth captured at load (\Gm@doctw), NOT the live \textwidth. A minipage
126% sets \textwidth=\linewidth locally, so `\linewidth=\textwidth` is true inside
127% one too; comparing to \Gm@doctw instead keeps a reduced \linewidth (nesting
128% minipage/parbox) untouched. Scoped to the picture's group, so the surrounding
129% HTML flow is never touched.
130\def\Gm@applysvgwidth{%
131  \ifdim\linewidth=\Gm@doctw
132    \linewidth=\Gm@tw \columnwidth=\Gm@tw \hsize=\Gm@tw \textwidth=\Gm@tw
133    \textheight=\Gm@th
134  \fi}
135
136% Install the picture hooks after all packages have loaded (tcolorbox/tikz/pgf
137% are raw-loaded and only then defined). Prepend, so the width is in force
138% before the box reads its `width=...\linewidth` key.
139\AtBeginDocument{%
140  \@ifundefined{tcolorbox}{}{%
141    \let\Gm@orig@tcolorbox\tcolorbox
142    \def\tcolorbox{\Gm@applysvgwidth\Gm@orig@tcolorbox}}%
143  \@ifundefined{tikzpicture}{}{%
144    \let\Gm@orig@tikzpicture\tikzpicture
145    \def\tikzpicture{\Gm@applysvgwidth\Gm@orig@tikzpicture}}%
146  \@ifundefined{pgfpicture}{}{%
147    \let\Gm@orig@pgfpicture\pgfpicture
148    \let\Gm@orig@endpgfpicture\endpgfpicture
149    % \pgfpicture opens its own group internally, so wrap it in an explicit
150    % group of our own to keep the width change from leaking past the picture.
151    \def\pgfpicture{\begingroup\Gm@applysvgwidth\Gm@orig@pgfpicture}%
152    \def\endpgfpicture{\Gm@orig@endpgfpicture\endgroup}}%
153}
