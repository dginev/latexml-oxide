1//! ltxtable.sty — `\LTXtable{width}{file}`: a longtable with tabularx `X`
2//! columns whose body lives in a separate file.
3//!
4//! The real macro (ltxtable.sty:9-56) runs tabularx's trial loop over
5//! `\input{#2}` (a `longtable` environment) with longtable's `\LT@echunk`/
6//! `\LT@get@widths` chunk machinery to converge the `X` widths, then inputs
7//! the file once more for real. Neither Perl nor Rust had a binding, and the
8//! raw macro reaches `\TX@target`/`\TX@col@width`/`\TX@newcol`/`\LT@echunk`/
9//! `\LT@get@widths` — internals the tabularx/longtable bindings do not model
10//! (tikzcodeblocks-documentation 64 errors, vhistory examples). As with the
11//! xltabular binding, `X` is a global column type once tabularx is loaded and
12//! longtable's alignment accepts it, so the width trial is unnecessary here:
13//! `\LTXtable` sets the target width for the record and inputs the file once.
14use latexml_package::prelude::*;
15
16LoadDefinitions!({
17  RequirePackage!("tabularx");
18  RequirePackage!("longtable");
19  // ltxtable.sty:8 `\TX@target#1\relax` is the width tabularx distributes
20  // over the X columns; keep it as a real dimen so packages reading it
21  // (`\TX@target`, `\TX@col@width`) find a length.
22  RawTeX!(
23    r"\ifx\TX@target\@undefined\newdimen\TX@target\fi\ifx\TX@col@width\@undefined\newdimen\TX@col@width\fi"
24  );
25  DefMacro!(
26    "\\LTXtable{}{}",
27    r"\begingroup\TX@target#1\relax\TX@col@width\TX@target\input{#2}\endgroup"
28  );
29});
