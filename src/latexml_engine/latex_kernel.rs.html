1//! Loading the LaTeX format on demand — the eager trigger list's safety net.
2//!
3//! `TeX.pool` installs the Perl-faithful autoload triggers (`TeX.pool.ltxml`
4//! L33-56: `\documentclass`, `\newcommand`, `\begin`, …), each a macro that
5//! expands to `\@load@latex@pool <trigger>`. Those fire *eagerly*, on a
6//! legitimate use, before any error is raised — and they stay exactly as Perl
7//! writes them.
8//!
9//! But a curated list is incomplete by construction: real LaTeX has no "before
10//! the kernel" (`latex.ltx` *is* the format), so a document may legitimately
11//! open with any kernel command. Anything not on the list was simply undefined
12//! — stubbed as `<ltx:ERROR/>`, with the document derailing from there. The
13//! canonical witness is the "use this class if installed" idiom
14//!
15//! ```tex
16//! \IfFileExists{proc-l.cls}{\documentclass{proc-l}}{\documentclass{amsproc}}
17//! ```
18//!
19//! (arXiv 2605.25877 line 4, 2606.06905, 2606.09693, 2606.16723): with
20//! `\IfFileExists` undefined the conditional collapses, *no class is ever
21//! selected*, and the run cascades into `Fatal:TooManyErrors`. Same-host Perl
22//! LaTeXML fails identically — see `docs/parity/KNOWN_PERL_ERRORS.md`.
23//!
24//! [`autoload_latex_kernel`] closes the gap generally: registered into
25//! `latexml_core::binding::kernel_autoload`, it is consulted at the two
26//! undefined-CS paths (gullet `read_x_token`, stomach `invoke_token_undefined`)
27//! *instead of* erroring, and answers "is this a LaTeX kernel command?" — if so
28//! the format loads and the token is retried. It subsumes the two Rust-only,
29//! witness-driven trigger accretions that used to sit in `tex.rs`'s list:
30//! `\UseRawInputEncoding` (witness 2403.19280) and `\DocumentMetadata`
31//! (witness 2305.08034), which are now just two instances of "a kernel CS used
32//! before the format loaded".
33//!
34//! # The membership oracle is the DUMP, not `latex.ltx`
35//!
36//! The question that has to be answered *before* committing to a load is "what
37//! will be defined **after** `LaTeX.pool` loads?" — because "load it and see if
38//! that helped" would drag the kernel into genuinely plain-TeX documents on
39//! their first undefined CS.
40//!
41//! The right oracle for that is `latex.YYYY.dump.txt`, and deliberately **not**
42//! the host's `latex.ltx`. The dump is not a "YYYY artifact": it is generated by
43//! *our current code* inside a pinned TL-YYYY container, and it is the
44//! **executed** result of that bootstrap — the state delta this engine actually
45//! reaches. `latex.ltx` is source text, so answering the same question from it
46//! would mean re-deciding every `\def` / `\let` / `\csname` / `\@namedef` /
47//! `\ifx` in the file, i.e. re-running the load we are trying to avoid. It is
48//! also the very artifact `LaTeX.pool` goes on to replay, so a catalogue built
49//! from it cannot disagree with what the load installs.
50//! **Do not "correct" this to `latex.ltx`.**
51//!
52//! Only the backward direction exists. A control sequence newer than the
53//! ambient dump year is out of scope by design — we cannot predict a TeX Live
54//! that has not shipped, and the host TeX Live of that age does not have the
55//! command either, so reporting it undefined is correct. There is no
56//! forward-compat seam and none is wanted.
57//!
58//! # Degraded (no-dump) branch
59//!
60//! `LoadFormat('latex')` has two mutually exclusive branches (CLAUDE.md durable
61//! parity rule 1). On the degraded one — `$LATEXML_NODUMP`, or no dump
62//! reachable at all — there is no key set to test against, so
63//! [`latex_kernel_defines`] is always `false` and this mechanism never fires.
64//! Behaviour there is bit-identical to before: the Perl `TeX.pool` L33-56
65//! trigger list remains the only mechanism — in a plain TeX document, where
66//! those triggers are held undefined ([`LATEX_TRIGGERS`]), it acts on them
67//! alone, as their definitions would.
68//!
69//! # Plain TeX documents
70//!
71//! A plain TeX document (`state::plain_tex_document`) is compiled by TeX, with
72//! no LaTeX to fall back on: a LaTeX kernel command there is undefined, and the
73//! format loads only on a use of one of Perl's triggers.
74

82// Process-once cached env var (see WISDOM #56 — getenv hot-path race).
83static INI_MODE: Lazy<bool> = Lazy::new(|| std::env::var_os("LATEXML_INI_MODE").is_some());

85/// Per-session flag: the kernel autoload has already been attempted.
86///
87/// Necessary and not redundant with `LaTeX.pool_loaded`, which
88/// `input_definitions` only sets *after* the pool body has run — so without
89/// this the load could re-enter itself through its own undefined CSes. It is a
90/// State value, so it resets with the session (a test binary runs many
91/// conversions on one thread) while surviving group pops (assigned globally).
92const AUTOLOAD_ATTEMPTED: &str = "LaTeX.pool_autoload_attempted";

94thread_local! {
95  /// Control-sequence names the ambient kernel dump defines. Built at most once
96  /// per process, and only on the cold path below — never at startup, so the
97  /// ~161 ms per-process bootstrap is untouched. ~22k boxed names (<1 MB) that
98  /// only ever materialise in a session that reached an undefined CS with no
99  /// LaTeX format loaded.
100  static KERNEL_CS: OnceCell<FxHashSet<Box<str>>> = const { OnceCell::new() };
101}

103/// The Perl `TeX.pool` LaTeX triggers (`TeX.pool.ltxml` L33-39), each a macro that loads the format and re-reads
104/// itself (`tex.rs`).
105///
106/// A plain TeX document holds them undefined (OXIDIZED_DESIGN_DIVERGENCES #536). Generic-format files probe these
107/// names to tell LaTeX from plain TeX — pst-xkey.tex:44 `\ifx\ProvidesFile\@undefined`, iftex.sty:31-33 (and
108/// eplain.tex:47-49, its inlined copy) `\csname ProvidesPackage\endcsname`, atbegshi.sty:155-156 and the other Oberdiek packages
109/// `\csname RequirePackage\endcsname`, dual-mode files `\ifx\documentclass\undefined` — and Perl's defined trigger
110/// answered "LaTeX": the file took its LaTeX branch, which loaded the format in the middle of a plain document
111/// (math0305287, math0111222: pstricks; the eplain papers on TL 2025). Held undefined, a probe sees what TeX sees, and a
112/// *use* still loads the format, now through [`autoload_latex_kernel`].
113pub const LATEX_TRIGGERS: [&str; 16] = [
114  "\\documentclass",
115  "\\newcommand",
116  "\\renewcommand",
117  "\\newenvironment",
118  "\\renewenvironment",
119  "\\NeedsTeXFormat",
120  "\\ProvidesPackage",
121  "\\RequirePackage",
122  "\\ProvidesFile",
123  "\\makeatletter",
124  "\\makeatother",
125  "\\begin",
126  "\\listfiles",
127  "\\nofiles",
128  "\\typeout",
129  "\\PassOptionsToPackage",
130];

132/// Load `LaTeX.pool`, the way the `\@load@latex@pool` trigger primitive does.
133///
134/// Single definition of "pull the LaTeX format in", shared by that primitive
135/// and by [`autoload_latex_kernel`], so the post-load fixups can never diverge
136/// between the eager and the on-undefined route.
137pub fn load_latex_pool() -> Result<()> {
138  input_definitions("LaTeX", InputDefinitionOptions {
139    extension: Some(Cow::Borrowed("pool")),
140    ..InputDefinitionOptions::default()
141  })?;
142  // Restore our `\documentstyle` impl after the LaTeX pool load. The
143  // latex_dump unconditionally redefines `\documentstyle` to the
144  // kernel-style `\input{latex209.def}\documentclass`; in Perl that's
145  // overridden by latex_constructs.pool.ltxml's DefConstructor, but
146  // our latex_constructs.rs port doesn't redefine it. Re-Let to our
147  // backup to win. See tex_job.rs `\lx@documentstyle@impl` for the
148  // full diagnostic context (hep-th9912229 witness).
149  Let!("\\documentstyle", "\\lx@documentstyle@impl");
150  Ok(())
151}

153/// Does loading `LaTeX.pool` define `cs`? See the module docs for why the
154/// ambient kernel dump is the oracle. `false` on the degraded no-dump branch.
155pub fn latex_kernel_defines(cs: &str) -> bool {
156  KERNEL_CS.with(|cell| cell.get_or_init(build_kernel_catalogue).contains(cs))
157}
158
159fn build_kernel_catalogue() -> FxHashSet<Box<str>> {
160  // Same resolver `latex_dump::load_definitions` uses (env overrides, ambient
161  // year, embedded fallback), so the catalogue can never name a CS from a
162  // different dump than the one the pool would load. Key scan only — no record
163  // is parsed and no State is touched.
164  match crate::latex_dump::resolve_dump_text() {
165    Some((content, _label, _year, _from_embedded)) => dump_reader::collect_meaning_keys(&content),
166    None => FxHashSet::default(),
167  }
168}

170/// The `latexml_core::binding::kernel_autoload` hook: `true` means the LaTeX
171/// format was just loaded *and* `token` now has a meaning, so the caller must
172/// retry it; `false` means take the ordinary bounded `Error:undefined` path.
173pub fn autoload_latex_kernel(token: &Token) -> bool {
174  if token.get_catcode() != Catcode::CS {
175    return false;
176  }
177  // Dump-build (`--init=plain.tex` / `--init=latex.ltx`) raw-loads a format
178  // file against a deliberately minimal state and writes the delta. Pulling
179  // `LaTeX.pool` in from an undefined CS there would put the whole pool into
180  // the snapshot — i.e. a previous run's dump would leak into the next one.
181  // The dump must be built from the format file alone.
182  if *INI_MODE || crate::dump_paths::building_format() {
183    return false;
184  }
185  // The caller has declared that undefined CSes in this stretch are expected
186  // forward references that later fixups resolve (expl3-code.tex and friends).
187  // Acting on one would load the format on a name that is about to be defined
188  // anyway. Same gate the undefined-CS `Error!` sites use.
189  if lookup_bool("SUPPRESS_UNDEFINED_ERRORS") {
190    return false;
191  }
192  // Once the format is in, the question is moot: the CS is either defined or
193  // genuinely undefined.
194  if lookup_bool("LaTeX.pool_loaded") {
195    return false;
196  }
197  if lookup_bool(AUTOLOAD_ATTEMPTED) {
198    return false;
199  }
200  // A plain TeX document (`state::plain_tex_document`, arXiv AutoTeX's test) is compiled by TeX without LaTeX: there a
201  // LaTeX kernel command is an undefined control sequence, as TeX and Perl report it. Loading the format on it put
202  // LaTeX's `\verbatim` into plain documents (read to the end of the file: 1504.02513, 1402.1807, 1310.8121,
203  // 2405.04530), LaTeX's `\title` (math9810192) and, through a `\let\big=\eightbig` of an undefined name, the whole
204  // format mid-file (1901.09683). Only Perl's own triggers, held undefined there ([`LATEX_TRIGGERS`]), load it on a
205  // use, as their definitions do in a LaTeX document — with or without a dump.
206  if plain_tex_document() {
207    if !token.with_cs_name(|cs| LATEX_TRIGGERS.contains(&cs)) {
208      return false;
209    }
210  } else if !token.with_cs_name(latex_kernel_defines) {
211    return false;
212  }
213  // Claim the single attempt BEFORE loading. The pool load runs arbitrary
214  // definition code that can itself reach an undefined CS, and re-entering
215  // here would recurse; a trigger that re-emits itself spins the gullet
216  // forever, silently, with no error for `too_many_errors` to cap (witness
217  // 2606.21610, see the `def_autoload` closure in `tex.rs`).
218  assign_value(AUTOLOAD_ATTEMPTED, true, Some(Scope::Global));
219  let cs_name = token.with_cs_name(|cs| cs.to_string());
220  Info!(
221    "autoload",
222    "LaTeX",
223    s!("{cs_name} is a LaTeX kernel command — loading LaTeX.pool")
224  );
225  // Hoist whatever the load installs at the current frame up to global: this
226  // can fire at any group depth (unlike the eager triggers, which in practice
227  // fire at top level), and definitions popped by the enclosing `}` would
228  // leave `LaTeX.pool_loaded` set with the format gone. Same guard
229  // `def_autoload` uses in `tex.rs`.
230  let pre_keys = snapshot_top_frame_keys();
231  if let Err(e) = load_latex_pool() {
232    Warn!(
233      "autoload",
234      "LaTeX",
235      s!("failed to load LaTeX.pool for {cs_name}: {e}")
236    );
237    return false;
238  }
239  hoist_top_frame_package_load(&pre_keys);
240  // The format may still not define it (e.g. a dump key our own LaTeX pool
241  // later clears). Then this was a no-op and the caller reports it undefined,
242  // exactly as before.
243  has_meaning(token)
244}
