§Environment variables

Every environment variable that latexml-oxide reads or sets, with the values it accepts, its default and its effect. A command-line flag always wins over the variable of the same meaning. Most variables are read once, when a conversion starts.

Audience legend

MarkWho it is for
useranyone running latexml_oxide from the command line
libraryRust code embedding the latexml crate
packagerbuilding, packaging or releasing the binaries
fleetcortex_worker deployments
devdiagnosing or measuring the converter; output and speed may change
testthe test suite only
internalset by latexml-oxide for its own child processes; never set these yourself

How values are read. Conventions differ between variables, so each row gives its own:

  • presence: the variable being set at all switches the feature on, whatever its value. LATEXML_NODUMP=0 also skips the dumps.
  • 1: only the exact value 1 switches it on.
  • 1|true|yes: one of those three values, case-sensitive.
  • 0 disables: the feature is on unless the value is exactly 0.
  • A number that does not parse falls back to the default, except LATEXML_MAX_MEMORY, which is a command-line error.

§Memory and limits

VariableValuesDefaultEffect
LATEXML_MAX_MEMORYMiB; 0 = no ceiling90 % of available RAM, at most 64 GiB, at least 2048 MiBThe one memory knob of latexml_oxide, the same as --max-memory. The watchdog stops the run above it; the cooperative fuse sits at 3/4 of it; streaming spills at a third of the fuse.
LATEXML_STREAMINGtrue / falseunset = automaticThe same as --streaming. true streams from the start; false never streams. 1 is rejected.
LATEXML_TOKEN_LIMITtokens; 0 disables20,000,000,000, raised to 1000 × the source sizeRunaway-expansion backstop (a Fatal). --token-limit wins. Setting it at all turns off the scaling with source size.
LATEXML_EXPAND_DEPTH_LIMITinteger; 0 disables12,000Nested expansion depth before Fatal:Timeout:Recursion.
LATEXML_MAX_GRAMMAR_LEXEMESinteger; 0 or none disables12,000Formulas longer than this skip the grammar parser for the simpler fallback parser.

Under an address-space limit (ulimit -v, as some batch systems impose), the allocators’ reservations count against the limit even though they use no memory. Two variables of the allocators themselves, not ours, cut that reservation by about half without changing memory use, speed or output:

VariableRecommendedEffect
MALLOC_ARENA_MAX2glibc: two malloc arenas instead of one per thread (each reserves 64-128 MiB).
MIMALLOC_ARENA_RESERVE128MiBmimalloc: reserve 128 MiB at a time instead of 1 GiB.

Without an address-space limit neither is needed. The fleet sets both for its children (see below).

§TeX Live

latexml-oxide finds packages, classes and fonts through kpathsea, so the usual TeX Live variables apply: TEXMFROOT, TEXMFDIST, TEXMFMAIN, TEXMFLOCAL, TEXMFHOME, TEXMFVAR, TEXMFCONFIG, TEXMFSYSVAR, TEXMFSYSCONFIG, TEXMFCNF, TEXINPUTS, BIBINPUTS and the other *INPUTS paths. A trailing / on a tree root is trimmed and logged. KPSEWHICH names the kpsewhich program that anchors kpathsea; PATH also finds the external tools (kpsewhich, ImageMagick, Ghostscript, mutool, pdftocairo, texlua).

The other tools/ scripts document their variables in their headers.

§The cortex worker fleet (fleet)

cortex_worker is configured by its command-line options. For each child process it starts it sets:

VariableValueWhy
TMPDIR, MAGICK_TEMPORARY_PATH, MAGICK_TMPDIRa fresh directory per worker slotScratch space emptied between spawns.
MALLOC_ARENA_MAX, MIMALLOC_ARENA_RESERVE2, 128MiBThe children run under an address-space limit (--child-mem-limit-mb); see “Under an address-space limit”.
MALLOC_CONF, _RJEM_MALLOC_CONFbackground_thread:true,dirty_decay_ms:500,muzzy_decay_ms:0Prompt return of freed memory in jemalloc builds.
LATEXML_RSS_CAP_BYTES--max-rss-mb, else --child-mem-limit-mb − 256 MiBThe per-child memory fuse.

These replace any value of the same name in the worker’s own environment. The Docker entrypoint reads WORKERS and PROFILE (ar5iv or generic).

§Tests (test)

LATEXML_BLESS, LATEXML_SAVE_ACTUAL, LATEXML_TEST_LOG, LATEXML_SIGSEGV_TRACE, LATEXML_TEST_TEXLIVE, LATEXML_TEST_SKIP_LOG, LATEXML_SVG_TESTS, LATEXML_BROWSER_TESTS, LATEXML_EPUBCHECK_TESTS, LATEXML_FIREFOX, LATEXML_BROWSER_ENGINE, LATEXML_FIREFOX_PATH, LATEXML_INJECT_PANIC, LATEXML_RENDER_TEST_SERIAL_STOP, LATEXML_RENDER_WORKER_TEST_ABORT, CORTEX_WORKER_TEST_FAULT, CORTEX_WORKER_TEST_GROW_MB, UPDATE_SUPPORTED_PACKAGES, UPDATE_API_DOC and LATEXML_PERL_LIB drive the test suite: blessing goldens, requiring optional tools (a missing mutool, browser or epubcheck becomes a failure instead of a skip), and fault injection. BUILDING.md describes the ones a contributor uses.
