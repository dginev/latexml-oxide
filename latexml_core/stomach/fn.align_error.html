tex.web §1127 align_error: a tab, \cr or \span that reaches the stomach while the alignment count is not 0 — the cell left a brace unbalanced, so the gullet did not take it for the cell’s end (§342) — gets the brace TeX supposes was omitted: count −1 or −2 (the cell’s } closed one more group than it opened, a} &=& b) inserts a { (“Missing { inserted”), count +1 or +2 ({a & b}, \textbf{a & b}) a } (“Missing } inserted”), and the column end is read again behind it, now at count 0, so the v-part runs and the cell ends as the template says (§789). The ledger moves as TeX’s does: align_error steps the count towards 0 and ins_error’s back_input (§325) retracts the inserted brace, which counts again when it is read. A larger count (abs(align_state)>2, “Misplaced &”) is left to the cell’s reader, as is a count past the v-part’s 1000000 (the column’s own end). Before, the column end was taken for the cell’s end with no v-part: an eqnarray/amsmath cell left its template’s math open (pdflatex 1 error, ours 17: “Attempt to close a group that switched to mode math”), and a tabular cell’s {a & b} lost a without a word. Perl has no align_error (KNOWN_PERL_ERRORS #923). Whether it fired. Guards perfect_kernel_batch70b::{eqnarray_stray_close_brace_inserts_a_left_brace, tabular_open_brace_at_a_cell_end_inserts_a_right_brace}.
